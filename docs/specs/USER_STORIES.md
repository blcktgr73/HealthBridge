# User Stories

상태: 설계 초안

## MVP 목표

사용자가 Android Phone에서 Health Connect 읽기 권한을 허용하고, 최근 7일의 최소 건강 요약과 운동·수면 세션을 수동 동기화하여 인증된 Presephone/OpenClaw webhook으로 전달할 수 있어야 합니다.

## Release 1 — 수동 동기화 가능한 최소 제품

### 권한과 연결

- US-001 사용자는 Health Bridge가 요청하는 Health Connect 읽기 권한 목록을 확인할 수 있어야 한다.
- US-002 사용자는 필요한 읽기 권한만 허용할 수 있어야 한다.
- US-003 사용자는 Health Connect를 사용할 수 없는 기기에서 명확한 안내를 받아야 한다.
- US-004 사용자는 언제든 앱에서 권한 상태를 다시 확인할 수 있어야 한다.

### 데이터 수집과 정규화

- US-010 사용자는 최근 7일을 기본 범위로 수동 동기화를 실행할 수 있어야 한다.
- US-011 앱은 걸음, 거리, 활동 칼로리, 운동 세션, 수면 세션을 읽을 수 있어야 한다.
- US-012 앱은 페이지 토큰을 소비하여 지정 범위의 레코드를 누락 없이 읽어야 한다.
- US-013 앱은 `health.v1` 정규화 payload를 생성해야 한다.
- US-014 값이 없는 필드를 0으로 임의 대체하지 않아야 한다.
- US-015 앱은 날짜 경계와 원본 timezone을 보존해야 한다.

### 전송과 복구

- US-020 사용자는 endpoint URL과 기기별 인증 토큰을 등록할 수 있어야 한다.
- US-021 앱은 인증된 HTTPS POST로 payload를 전송해야 한다.
- US-022 앱은 동일 payload를 재전송해도 서버에서 중복 반영되지 않도록 idempotency key를 보내야 한다.
- US-023 전송 실패 시 payload를 암호화된 로컬 큐에 보관하고 재시도해야 한다.
- US-024 사용자는 마지막 동기화 시각과 성공·실패 상태를 확인할 수 있어야 한다.
- US-025 사용자는 저장된 endpoint 토큰과 로컬 대기 데이터를 폐기할 수 있어야 한다.

## Release 2 — 증분 및 자동 동기화

- US-030 앱은 Health Connect 변경 토큰을 저장하고 추가·수정·삭제 변경을 반영해야 한다.
- US-031 변경 토큰 만료, 권한 철회, 앱 재설치 시 전체 재동기화 절차를 제공해야 한다.
- US-032 사용자가 별도로 허용한 경우에만 백그라운드 읽기를 활성화해야 한다.
- US-033 앱은 배터리와 Health Connect rate limit을 고려해 자동 동기화 주기를 조절해야 한다.

## Release 3 — 확장 데이터

- US-040 사용자는 별도 동의 후 심박수 데이터를 동기화할 수 있어야 한다.
- US-041 사용자는 별도 동의 후 체중 데이터를 동기화할 수 있어야 한다.
- US-042 workspace는 운동 세션과 심박수 기록을 이용해 강도 분석을 수행할 수 있어야 한다.

## 범위 제외

- Health Connect에 데이터를 쓰는 기능
- Samsung Health 직접 API 연동
- Telegram 또는 Discord를 통한 건강 원본 데이터 전송
- Android 앱 내부의 Zone 2 판정
